# 💅 Telegram-бот онлайн-записи на маникюр

Бот для мастера маникюра: клиенты сами выбирают услугу, дату и свободное время, а мастер получает
уведомления и управляет расписанием прямо в Telegram. Работает с одним мастером.

> Сюда стоит добавить GIF или скриншоты: запись клиента, «Мои записи», панель мастера.

## Возможности

**Клиент**
- пошаговая запись: услуга → дата → время → имя и телефон → подтверждение;
- показываются только реально свободные дни и время (с учётом длительности услуги, перерывов и выходных);
- постоянному клиенту имя и телефон повторно вводить не нужно;
- «Мои записи»: просмотр и отмена (не позднее чем за 2 часа до визита);
- напоминание за 24 часа до визита с кнопкой отмены;
- прайс и контакты с часами работы.

**Мастер**
- мгновенные уведомления о новых записях и отменах;
- расписание на сегодня, завтра и любую дату из ближайших двух недель;
- отмена записи клиента (клиент получает уведомление);
- закрытие и открытие дней (отпуск, болезнь);
- управление услугами командами `/addservice` и `/delservice`.

## Команды

| Команда | Кто | Что делает |
|---|---|---|
| `/start` | все | главное меню |
| `/book` | все | начать запись |
| `/my` | все | мои записи |
| `/price`, `/contacts` | все | услуги и цены, контакты |
| `/cancel` | все | прервать запись |
| `/admin` | мастер | панель мастера |
| `/addservice Название \| минуты \| цена` | мастер | добавить услугу |
| `/delservice номер` | мастер | скрыть услугу |

## Быстрый старт

Нужен Python 3.10 или новее.

```bash
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt

cp .env.example .env             # Windows: copy .env.example .env
# впишите в .env токен от @BotFather и свой Telegram ID (узнать: @userinfobot)

python bot.py
```

Откройте бота в Telegram и отправьте `/start`. Мастеру (аккаунту из `ADMIN_IDS`) тоже нужно один раз
нажать `/start` у бота, иначе Telegram не разрешит боту писать ему первым. Панель мастера: `/admin`.

## Настройка

**Переменные окружения (`.env`)**

| Переменная | Назначение |
|---|---|
| `BOT_TOKEN` | токен бота (обязательно) |
| `ADMIN_IDS` | Telegram ID мастера, несколько через запятую |
| `TIMEZONE` | часовой пояс салона, например `Europe/Moscow` |
| `PROXY_URL` | необязательно, например `socks5://127.0.0.1:10808` |
| `SALON_NAME`, `SALON_ADDRESS`, `SALON_PHONE`, `CURRENCY` | что показывать клиентам |
| `DB_PATH` | путь к файлу базы данных (по умолчанию `data/bookings.db`) |

**Расписание и правила — в `config.py`**
- `WORK_HOURS` — рабочие часы по дням недели (`None` — выходной);
- `BREAKS` — ежедневные перерывы, по умолчанию обед 14:00–15:00 (чтобы убрать: `BREAKS = ()`);
- `DEFAULT_SERVICES` — стартовые услуги (потом меняются командами мастера);
- в `Settings`: шаг сетки времени, минимальное время до записи, горизонт записи, время напоминания,
  правило отмены, лимит активных записей на клиента.

## Как это устроено

```
bot.py              сборка приложения, регистрация хендлеров, запуск
config.py           настройки, расписание, правила записи
db.py               SQLite: услуги, клиенты, записи, выходные дни
slots.py            расчёт свободных окон (чистые функции, без БД и Telegram)
booking.py          связка БД и slots: доступные дни и время для клиента
keyboards.py        reply- и inline-клавиатуры
reminders.py        фоновая задача напоминаний
handlers/
  common.py         /start, прайс, контакты, обработка ошибок, «устаревшие кнопки»
  client.py         диалог записи (ConversationHandler), «Мои записи», отмена
  admin.py          панель мастера
tests/              unit-тесты
```

Принятые решения:

- **Запись атомарна.** Проверка занятости и вставка записи выполняются в одной транзакции
  `BEGIN IMMEDIATE`, поэтому два клиента не займут одно время, даже если нажмут «Подтвердить»
  одновременно (есть тест на 8 параллельных попыток). Перед этим бот ещё раз сверяется с актуальным
  расписанием и, если время заняли, предлагает выбрать другое.
- **Расчёт окон — чистая функция** (`slots.free_slots`), поэтому она покрыта тестами: границы рабочего
  дня, перерывы, примыкающие записи, минимальное время до визита.
- **Напоминания через одну повторяющуюся задачу**, которая раз в минуту спрашивает базу, о чём пора
  напомнить. Ничего не нужно пересоздавать после перезапуска, отменённые записи не попадают в выборку,
  а тем, кто записался в последний момент, напоминание не присылается.
- **Время.** В базе хранится локальное время салона, часовой пояс задаётся явно (`zoneinfo`).
- **Услуги не удаляются, а скрываются**, чтобы не ломать историю записей.
- **Надёжность.** Устаревшие кнопки (например, после перезапуска) вежливо обрабатываются, ошибки
  собираются в одном обработчике, весь пользовательский ввод экранируется для HTML,
  а токен не попадает в логи (логирование `httpx` приглушено).

## Тесты

```bash
python -m unittest discover -v
```

Тесты покрывают расчёт окон, слой базы данных (включая гонку при записи и логику напоминаний),
загрузку настроек и вспомогательные функции.

## Запуск на сервере (systemd)

```ini
# /etc/systemd/system/manicure-bot.service
[Unit]
Description=Manicure booking bot
After=network-online.target

[Service]
WorkingDirectory=/opt/manicure_bot
ExecStart=/opt/manicure_bot/.venv/bin/python bot.py
Restart=always
User=botuser

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl enable --now manicure-bot
```

## Ограничения и идеи для развития

- Один мастер. Для нескольких нужны таблица мастеров и привязка записей и услуг к ним.
- Незавершённые диалоги записи хранятся в памяти и сбрасываются при перезапуске; решение —
  `PicklePersistence` из python-telegram-bot.
- Запросы к SQLite синхронные: для такой нагрузки это нормально, при росте можно перейти на
  `aiosqlite` или PostgreSQL.
- Идеи: свои часы работы на конкретную дату, блокировка отдельных интервалов, рассылка клиентам,
  предоплата, Dockerfile и webhook вместо long polling.
